五种 Output Style 对比

四种内置，一种自定义。它们改的都是系统提示词，但调的不是同一件事 —— 选错的代价通常不是"风格不喜欢"，而是该问你的时候没问、该说清的时候简化掉了。

01它们其实是三个旋钮

把五种摆在一条线上比较会失真。Proactive 和 Explanatory 根本不在争同一个东西 —— 一个管"要不要问你"，一个管"要不要讲给你听"。拆成三个旋钮才对得上：

Dial A — 自主度
要不要问你
Default 会在岔路口停下 · Proactive 自己做假设往前走
Dial B — 教学量
要不要教你
Explanatory 讲给你听 · Learning 留一段让你自己写
Dial C — 带宽
你现在能吸收多少
ELI5 是唯一一个拧这个旋钮的 —— 官方四种都没覆盖

Dial C 和前两个正交：它跟你的技术水平无关，只跟你此刻还剩多少脑力有关。资深工程师深夜十一点的带宽，可能比新人白天还低。这也是 ELI5 值得单独存在的理由。

02逐项对比

Style 核心机制 优点 真实代价 应用场景
Default 内置
原厂系统提示词，不追加任何东西 唯一被 Anthropic 大规模调优过的基准。token 最省，所有 skill 和 subagent 的行为假设都以它为准 做完了，但你不知道为什么。在陌生代码库里，它的"简洁"会变成不透明 熟悉的仓库、赶工、CI、-p 非交互调用
Proactive 内置
追加"立即执行、自主假设、行动优先"的指令 治"想太多"。机械任务和批量重构上，省掉大量来回确认 它砍掉的正是"停下来问" —— 而需求模糊时那恰恰最值钱。另外它不改权限模式，以为选了它就自主的人会配错 需求清晰 + 有 git 可回滚 + 任务机械
Explanatory 内置
在完成任务的间隙插入 Insights 讲的是"这个项目一贯怎么做" —— 代码库的既有惯例，是最难自己读出来的那部分 无条件插入，你已经懂的地方也讲。读久了开始跳过，然后连该读的也漏了。输出 token 明显上升 接手陌生仓库的前两周；review 别人的架构
Learning 内置
在代码里插 TODO(human) 标记，把关键片段留给你写 唯一一个改变你的行为、而不只是改变输出的 style。直接对抗"看它写完但自己写不出来" 会真的停下来等你，打断 flow。它挑的"strategic piece"未必是你想练的。完全不能用于后台或非交互运行 个人项目、学新语言、刻意练习
ELI5 自定义
锁死回答骨架（干了什么 → 成了没 → 下一步），加硬性简化规则 换了一根轴，管的是当下带宽而非技术水平。决策强制收敛成有限选项 + 它的倾向 "简化"会连不确定性和坏消息一起简化掉，除非显式豁免。而且它是开关不是配置 —— 忘了关就一直停在 5 岁版 深夜、脑子不转、只想知道下一步该干嘛

熟悉的活，只想省 tokenDefault

陌生代码库，想搞懂它的惯例Explanatory
自己的项目，想保持手感不退化Learning
脑子不转了，只想知道下一步ELI5

04五种共用的规则

  • 只作用于主对话。subagent 跑自己的系统提示词，不受 output style 影响（fork 是唯一例外，它继承父会话完整提示词）。工作流越依赖 subagent，换 style 的实际影响越小 —— 你调的只是汇报层。
  • 会话启动时读一次。改完必须 /clear 或开新会话才生效。这也是 /output-style 命令被移除的原因：中途切换会打断 prompt caching。
  • 桌面端没有选择菜单。只能直接写 settings 文件的 outputStyle 字段；/config 在这里只会打开设置面板。终端 CLI 里 /config 才有 picker。
  • 自定义 style 默认丢掉编码指令。frontmatter 不写 keep-coding-instructions: true，Claude Code 内置的软件工程指令会被整个替换掉。
  • 它是常驻税，不是按需加载。写成两千字的人格设定，等于每个 session 开局就交一笔 token。要复杂流程该用 skill 或 subagent，output style 只管语气、角色、默认输出格式。

05ELI5 参考实现

放在 ~/.claude/output-styles/eli5.md。相比 Lydia Hallie 的原版，补了坏消息豁免、格式约束和选项逃生口 —— 前者防止"简化"把风险一起抹掉，后者防止被框进假选择。

---
name: ELI5
description: Simple words, short answers, clear next step
keep-coding-instructions: true
---

It's been a long day and my brain is fried. Explain like I'm tired,
not like I'm stupid: simplify the wording, never the substance.

Small words, short sentences, short paragraphs. No tables, no nested
lists. If you have to use a technical term, explain it right after.
Only return what's actually necessary.

Just tell me what you did, did it work, what do I do now.

Never simplify bad news. If something failed, is unverified, or is
risky, say so plainly — that part does not get shortened.

If I have to decide something: 3 options max, the context I need to
pick fast, and which one you'd go with. Always leave room for me to
answer with something else entirely.

Keep paths and commands exact. I have no brain cells left for the rest.
内置四种的定义来自 Claude Code 官方文档；ELI5 基于 Lydia Hallie 公开的 eli5.md 改写。/output-style 命令已于 v2.1.91 移除，现统一通过 outputStyle 设置项切换。
