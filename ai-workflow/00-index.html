让 AI 帮你写代码,
但不失去对代码的控制

写给完全零基础的中文教程。它回答一个问题: 当 AI 替你写代码时,你凭什么相信它写对了? 从「什么是测试」讲到「怎么在流水线上建一道谁都绕不过的关卡」。

读这套教程需要什么 不需要会 Python、不需要用过 git、不需要写过测试、不需要懂 CI/CD。
需要一台 macOS / Linux / Windows 电脑、一个终端窗口(命令以 macOS 写法为基准,Windows 对照见第 2 页)、以及愿意亲手敲命令。

每个新名词按固定 5 步讲:① 一句话定义 → ② 生活化类比 → ③ 它在体系中的位置 → ④ 最小可运行例子 → ⑤ 常见误区。 术语第一次出现写成「中文(English)」,之后只用中文。
这套教程的内容是核对过的,不是凭记忆写的 所有命令、配置键名、插件参数、API 字段、版本号,都对照过官方文档或在真机上跑过。

本教程发现的三份「官方文档自己写错了」 这不是吹毛求疵,是你照抄会踩坑的地方:
  • SonarSource 官方示例的代码注释写反了 —— 说某参数会让构建变「黄」,实际是变「红」。网上大量教程照抄了这个错误(第 18 页第八节)
  • Coverage 插件官方 README 至今用着一个不存在的参数 —— 因为它的默认值恰好等于那个参数的效果,错了多年没人发现(第 18 页)
  • GitHub 官方教程页的版本号比它自己的代码仓库落后两个大版本(第 16 页)

这三个例子本身就是一课:为什么要自己实测,而不是抄博客。

怎么用这套教程

做法说明
只读不敲❌ 最没用的读法。全书有五个「亲手把代码改坏」的实验,不动手等于没读
边读边敲✅ 推荐。所有代码块都是完整的、可直接复制的,路径写全了,没有省略号
先跳到第 22 页如果你只是想查一条命令怎么写
抄第 13、14 页的提示词模板✅ 每条约束都有原因,第 14、20 页解释为什么
两件必须先做的事 ① 拿代码 —— 按下面那个框走 A 或 B,把配套项目拿到手。
② 搭环境 —— 进到那个目录,按第 2 页把虚拟环境、三个工具、pyproject.toml 弄好。

两样都要:第 2 页搭的是环境,不产出业务代码;A/B 拿到的是代码,不含虚拟环境 (.venv/ 按惯例不进存档)。齐了之后,从第 6 页起每一页都能立刻验证。

项目路径:全书命令里写作 <你的项目>/myshop。
📦 先把配套项目拿到手 全书的动手练习都在这个项目上, 没它就只能干读。两条路任选一条:

A · 直接克隆(推荐,自带完整存档历史) 
git clone https://github.com/Tree202/myshop-gate-demo.git myshop
拿到的就是第 19 页那个真机演示的仓库 —— 连它的提交历史都是教学资产。还没装 git?macOS 自带;Windows 到 git-scm.com 下载安装包 —— 第 2 页第二节末尾的 Windows 对照框里有详细说明。

B · 不用 git,下载压缩包 在 github.com/Tree202/myshop-gate-demo 页面点绿色的 Code → Download ZIP, 解压后把文件夹改名为 myshop。 这种方式拿不到存档历史,第 11–12 页需要你自己 git init —— 那时屏幕上会是 Initialized empty…;走 A 的人仓库已存在,会是 Reinitialized existing…,都正常。

那第 2 页算什么? 它搭的是环境,不是代码 —— 那一页不会建出 price.py、 order.py 这些业务文件(它自己也说了,那些第 6 页才真的建), 代码只能靠 A 或 B 拿;而 A/B 拿到的又没有 .venv。 所以不是二选一:先走 A/B 拿代码,再在拿到的目录里走第 2 页 (第 2 页里 mkdir、touch 那几步遇到已存在的文件,跳过就行)。

两样都齐了怎么验证:第 6 页第七节。
