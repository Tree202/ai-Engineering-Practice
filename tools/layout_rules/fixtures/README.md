## 为什么要把它们放进仓库

`check_layout.py` 的准入门槛是「原版必须报出已知缺陷、已修版必须不报」——
没有这一步,任何「0 个问题」都不可信:一个永远返回空的检查器也能得到它。

但原版目录在作者机器之外并不存在,于是版式巡检**只能在本机跑**,
`.github/workflows/check.yml` 长期只跑链接与口径两项。第三轮外部评审把这条列为 P2,
核验时又发现真正卡住的不是「云端没有基线」,而是脚本无基线时退出码恒为非零。

放进这两页(约 100 KB)之后,云端也拿得到真值样本,版式巡检才成为**真门禁**。

## 这两页覆盖哪些规则

| 规则 | 样本里的已知缺陷 | 期望条数 |
|---|---|---|
| `dangling_node` | 01 页七步图 5b / 5c / 兜底 三个节点有入边无出边 | 3 |
| `dangling_edge` | 01 页一条箭头停在步骤 7 方框外 10.8px | 1 |
| `grid_text` | 02 页 `.chk` 验收清单被 `display:grid` 拆成竖排 | 7 |

另有两条**阳性对照**(kb/05、kb/06,随仓库走,不依赖本目录)和一条**变异锁**:
往 01 页那张图注入一条右缘贴齐画布的通栏矩形后,缺陷仍须报满 3 条。
判据一旦退回「同列只比右边缘」,通栏矩形会和右列节点凑成「同列 2 个」,
把「兜底」整条吞掉(实测 3 → 2)。
