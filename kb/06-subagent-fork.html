子代理与分身：让别人替你干活

对话越聊越长，上下文快满了，这时候还要它「把整个对话整理成 8 个 HTML 文件」—— 这活儿一开始就注定要撑爆。
这一章讲的两个工具，专门解决这个问题。

1. 子代理是什么

子代理（Subagent）

subagent · .claude/agents/

1一句话定义
Claude 派出去的一个独立助手：它有自己的系统提示词、自己的工具、自己的上下文， 干完活只把最终结论报回来。
2生活化类比
像你请一个外包：你写一份需求文档发过去，他在自己那边翻资料、试方案、 改了十几版——这些过程你一概看不到，最后他交给你一份成果。 你的办公桌上只多了这一份成果，没多那十几版草稿。
3在体系中的位置
它和技能是并列的两种扩展方式： 技能是「给当前这个 Claude 加一段指令」， 子代理是「另开一个 Claude 去干」。
和分身是近亲——分身是子代理的一种特殊形态。
4最小例子
~/.claude/agents/code-reviewer.md
---
name: code-reviewer
description: 代码审查专家。写完代码后使用。
tools: Read, Grep, Glob, Bash
model: sonnet
---

你是一位资深代码审查员，从质量和安全角度审查代码。
5常见误区

❌ 以为它知道你们刚才聊了什么。不知道。它从零开始， 只看得到派活时给它的那段话。你说的「按上面的要求做」，它完全不知道"上面"是什么。

❌ 以为你设的输出风格对它也生效。不生效（第 04 章第 8 节）， 它用的是自己的系统提示词。所以它可能给你返回英文。

💡 子代理确实会拿到的东西

虽然它看不到对话历史，但这些还是会给它：

  • CLAUDE.md 文件（内置的 Explore 和 Plan 两种除外）
  • Git 状态快照
  • 在 skills 字段里预加载的技能（注意：预加载时是全文注入， 不像普通会话那样只放 description）
  • 同批其他代理的名册，方便互相发消息（需 v2.1.206+）

而主对话的自动记忆不会给它。

2. 分身是什么

分身（Fork）

context: fork · /subtask

1一句话定义
一种特殊的子代理：它继承你们到目前为止的全部对话， 但它干活的过程不会占用你的主对话，只把最终结果送回来。
2生活化类比
不是请外包，而是「复制一个此刻的你」： 这个复制体完整记得刚才开的每一场会，你不用给他做任何交接。 他到隔壁房间去把活干完，回来只汇报结论， 他在隔壁翻的那一堆资料，不会堆到你桌上。
3在体系中的位置
分身是子代理的特例： 它放弃了子代理的"输入隔离"（它看得到一切）， 但保留了"输出隔离"（过程不回流）。
换句话说：子代理是双向隔离，分身是单向隔离。
4最小例子
/subtask 根据我们刚才讨论的解析器改动，写一批单元测试

注意这句话里的「刚才讨论的」——只有分身能听懂，普通子代理不行。

5常见误区

❌ 以为分身是"更强的子代理"。不是强弱，是取舍。 分身丢掉了子代理最大的优点——输入隔离。 如果你希望它带着干净的脑子重新看问题，反而该用普通子代理。

❌ 以为它跑完主对话就变干净了。主对话确实不会被它的过程污染， 但它带过去的是"此刻的完整对话"——如果此刻已经很满了，分身那边一样满。 分身省的是后续的消耗，不是已有的。

3. 一张表看清两者区别

对比项分身（Fork）普通子代理（Subagent）
完整对话历史✅ 继承❌ 从零开始
系统提示词✅ 和主会话相同❌ 用它自己定义里的
工具✅ 同一套工具池❌ 用 tools 字段指定的那些
模型✅ 和主会话相同❌ 用 model 字段，或继承
输出风格✅ 生效❌ 不生效
CLAUDE.md✅ 加载✅ 加载（Explore / Plan 除外）
主对话的自动记忆❌ 不加载❌ 不加载
提示词缓存和主会话共享独立的缓存
过程是否回流主对话❌ 不回流，只回结果❌ 不回流，只回结果
💡 用一句话记住

子代理 = 双向隔离（它看不到你，你看不到它的过程）
分身 = 单向隔离（它看得到你，但你看不到它的过程）

4. 怎么用分身：/subtask

/subtask 把我们刚才讨论的内容整理成 HTML，写到 ./kb/ 目录
⚠️ 版本很重要
你的版本命令
v2.1.212 及以上/subtask
v2.1.161 ～ v2.1.211/fork（旧名）

查版本：

claude --version

或者在会话里打 /status。

分身跑起来是什么体验

现象说明
后台运行在交互式会话里，分身默认在后台跑，你可以继续在主对话里干别的
权限弹窗它需要权限时，弹窗出现在你的主会话里，并会写明是哪个子代理在申请
工具调用它调工具的过程不进你的主对话
结果只有最终结果回到主对话，你的上下文保持干净

5. 让技能跑在分身里：context: fork

更实用的做法：把分身写进技能的配置里，这样每次调用这个技能都自动在分身里跑。

~/.claude/skills/kb/SKILL.md（片段）
---
description: 把当前对话整理成初学者中文 HTML 教程
disable-model-invocation: true
context: fork
---

把本次对话中出现的知识，整理成 HTML 教程……
字段作用默认
context: fork这个技能在分身里跑不写就是在主对话里跑
agent指定用哪种子代理类型默认类型
background设 false = 等结果回来再继续这一轮；
默认 true = 后台跑，你可以继续干别的		true（需 v2.1.218+ 才能设 false）
model配合 context: fork 时，改的是分身的模型继承
💡 为什么这对「整理对话」特别合适

把三件事连起来看：

  1. 整理知识必须读完整个对话 → 普通子代理不行，只有分身能做
  2. 生成 8 个 HTML 文件会消耗大量上下文 → 在主对话里做，必定触发压缩
  3. 分身写文件到磁盘，只把「写了 8 个文件」这句话回传 → 主对话几乎没被消耗

这正好也印证了第 01 章那条原则： 让成果尽早离开上下文，进入硬盘。

6. 分身模式要不要手动开

场景分身模式怎么开
交互式会话（你平时打字聊天） ✅ v2.1.232 起默认开启 不用管，/subtask 直接能用
非交互模式（-p 参数）和 Agent SDK ❌ 默认关闭 CLAUDE_CODE_FORK_SUBAGENT=1
💡 开和不开的区别

开着：Claude 可以自己主动请求开一个分身，而且子代理默认在后台跑。
关着：/subtask 照样能用，只是得你亲手发起，Claude 不会主动要。

7. 怎么定义一个自己的子代理

子代理和技能一样，也是「一个 Markdown 文件」。存放位置：

位置范围
~/.claude/agents/你所有项目
.claude/agents/当前项目（可提交到 Git 共享）
插件的 agents/启用插件的地方，命名为 插件名:代理名
受管设置目录全组织
--agents 启动参数仅本次会话（传 JSON）

前置数据字段

字段必填作用
name✅唯一标识，只能用小写字母和连字符
description✅Claude 靠它判断什么时候该派这个代理去干活
tools它能用哪些工具
model用哪个模型
skills预加载哪些技能（全文注入，不只是描述）
memory让它维护自己独立的自动记忆
其他disallowedTools、permissionMode、maxTurns、 mcpServers、hooks、background、effort、 isolation、color、initialPrompt
⚠️ 别忘了它看不到对话

自定义子代理最常见的失败原因，就是派活时给的信息不够。 因为它什么背景都没有，你（或 Claude）派活时的那段话必须自包含： 文件路径写全、术语解释清楚、别说"照上面说的做"。

8. 什么时候用哪个

你的情况用什么为什么
「把刚才聊的整理成文档」 分身 需要完整对话历史，只有分身有
对话已经很长，还要做一件很吃上下文的事 分身 过程不回流，主对话保持干净
想从几个不同角度同时试方案 分身（多开几个） 它们都从同一个起点出发，结果可比
「去代码库里找出所有用到 X 的地方」 普通子代理 翻文件会产生海量中间输出，正好要隔离掉；而且它不需要知道你们聊过什么
想让它带着干净的脑子重新审视 普通子代理 不受前面讨论的思路影响
一件小事，几步就完了 都不用 派代理本身也有开销，小事直接做更快

本章小结

要点记住这一句
子代理从零开始的独立助手，看不到你们的对话
分身继承完整对话的子代理，过程不回流主对话
一句话区分子代理=双向隔离，分身=单向隔离
怎么发起分身/subtask 要干的事（v2.1.212+；更早叫 /fork）
让技能跑在分身里前置数据加 context: fork
要手动开吗交互式会话 v2.1.232+ 默认开；-p 模式要 CLAUDE_CODE_FORK_SUBAGENT=1
输出风格对子代理无效，对分身有效
