## 语言

- 回答一律用中文。
- 检索和查阅文档时用英文关键词，但不要把用户的中文原话翻译后再理解。

## 读者设定

用户是初学者。遇到用户可能没接触过的名词时，按固定五步讲：

1. 一句话定义，不使用行话
2. 一个生活化类比
3. 它在整个体系中的位置：和已讲过的名词是包含 / 并列 / 替代 / 前置哪种关系
4. 一个能照抄跑通的最小例子
5. 一到两个初学者常见误区

术语首次出现写成「中文（English）」，之后只用中文。

## 表达

- 讲解顺序从易到难，后面的内容只依赖前面已讲过的名词。
- 涉及对比、多个选项、多个字段时，用表格而不是长段文字。
- 涉及命令、配置、路径时，先核对官方文档再回答；
  不确定的明确标「⚠️ 待验证」，不要猜。

然后启用它：

  "outputStyle": "小白中文讲解"

3. 第二步：建 CLAUDE.md

你的学习项目根目录 / CLAUDE.md
# 这个项目是什么

我的 Claude Code 学习笔记库。用来把学到的东西整理成 HTML 教程自己看。

# 输出规范

- 知识库 HTML 输出到 `./kb/`
- 文件名：`00-index.html`（索引）、`01-<英文短名>.html` 依次编号
- 所有页面共用 `./kb/style.css` 和 `./kb/app.js`，不要在每页内联重复的样式
- 单个 HTML 正文控制在 600–900 行，超了就拆成新文件
- 不引任何外部 CDN、字体、图片；页面必须离线可打开
- 图示一律用手写内联 SVG
💡 三条经验

（1）保持在 200 行以内——它每次会话都全文加载。

（2）写能验证的话。「600–900 行」比「适合阅读的长度」有用得多。但定了就要真去验——本知识库 8 页实测正文 197–667 行，5 页不在区间内：可验证的约束配上不执行的检查，等于没写。

（3）想确认它真的被加载了，打 /context 看 Memory files 一栏。

# 对话 → 初学者知识库

把**本次对话**中出现的知识，整理成零基础也能看懂的中文 HTML 教程。
主题：$0（为空时自行归纳）　输出目录：$1（为空时用 `./kb/`）

## 工作流程（严格按顺序，不要跳步）

### 第 1 步　盘点大纲 → 停下来等我确认

列出本次对话涉及的**全部**知识点，做成表格：
编号 / 知识点 / 难度(★☆☆) / 归入哪个 HTML 文件。
**输出大纲后必须停下，等我说"继续"再写 HTML。** 这一步不生成任何文件。

### 第 2 步　核实

对每一条关于命令、配置、路径的说法：
- 用**英文关键词**检索官方文档核对
- 标注版本 / 环境要求
- 查不到或不确定的，明确标 `⚠️ 待验证`，**不要猜**

### 第 3 步　逐个生成（一次一个文件）

**写完一个 HTML 立刻落盘，再写下一个。** 不要攒到最后一起写。
每写完一个，回一行 `✅ 01-xxx.html 已写入（覆盖第 3、4、7 条）`。

### 第 4 步　自检

对照第 1 步的大纲逐条打钩，报告：已覆盖 N 条 / 遗漏哪些 / 哪些标了待验证。

## 输出规范

- 文件名：`00-index.html`（索引）、`01-<英文短名>.html` 依次编号
- 单文件正文 600–900 行，超了就拆；宁可多拆文件，不牺牲内容
- 每页顶部固定导航：`← 上一页　目录　下一页 →` + 主题切换
- `00-index.html` 列出所有分页、每页一句话摘要、推荐阅读顺序

## 样式

复用同目录下的 [template.html](template.html)。不要自己另写一套配色。
可用组件：`.concept` 概念卡 ｜ `.callout.tip/.warn/.danger` 提示框 ｜
`table` 对比表 ｜ `.steps` 步骤 ｜ `pre>code` 代码块 ｜ `.figure` 图示

## 硬性约束

- **不丢内容**：对话里每个知识点都必须在某页有落点
- **不编造**：不确定就标 `⚠️ 待验证`
- 每个概念至少配一张对比表格或一个可运行例子；每章至少一张流程图
- 图示用手写内联 SVG；不引任何外部 CDN、字体、图片
- 代码块可直接复制，路径写完整，不写省略号
⚠️ 这份 SKILL.md 踩了第 03 章讲过的坑（故意留着当教学点）

第 03 章说过：allowed-tools 的预授权只在调用它的那一轮有效。 而这份流程第 1 步要求「停下等我说‘继续’」——“继续”是下一条消息， 真正批量写文件的那一轮，预授权已经失效了，会重新弹窗。

两条出路：接受第二轮重新授权（多点一次确认，换来一次人工把关，不亏）； 或把「盘点」与「生成」拆成两个技能分两次调用，每次各自带预授权。

7. 拆解：三主题切换是怎么实现的

你现在看的这个页面，右上角有三个按钮。它是这么做的——只有三个要点。

要点一：用 CSS 变量，而不是到处写颜色

style.css
:root{                      /* 浅色是基准 */
  --bg:#ffffff;
  --text:#18181b;
  --accent:#bd5a20;
}
html[data-theme="dark"]{    /* 深色只覆盖需要变的几个 */
  --bg:#131316;
  --text:#ececee;
  --accent:#e8935c;
}

body{ background:var(--bg); color:var(--text); }
💡 CSS 变量（CSS Variables）

一句话：给颜色起个名字，用的地方写名字，换主题时只换名字对应的值。

类比：像 Excel 里把税率放在 B1 单元格，所有公式引用 $B$1。 改税率只改一个格，不用把每条公式都翻一遍。

好处：body 那行代码一个字都不用改， 只要 <html> 上的 data-theme 一变，整页颜色全变。

要点二：存「偏好」，不存「结果」

app.js（核心逻辑）
var KEY = 'kb-theme';
var mq = window.matchMedia('(prefers-color-scheme: dark)');

function getPref() {
  try { return localStorage.getItem(KEY) || 'dark'; }  // 没存过 → 默认深色
  catch (e) { return 'dark'; }                          // 隐私模式可能抛异常
}

function apply() {
  var pref = getPref();                     // 'light' | 'dark' | 'system'
  var real = (pref === 'system')
    ? (mq.matches ? 'dark' : 'light')       // 跟随系统 → 现场换算
    : pref;
  document.documentElement.dataset.theme = real;   // 写到 <html data-theme="...">
}
💡 这里最关键的设计

localStorage 里存的是三个值之一：light / dark / system—— 也就是用户的选择；而 <html data-theme> 上写的永远只有 light 或 dark—— 也就是换算后的结果。

为什么要分开？如果你把「跟随系统」当时算出来的 dark 直接存进去， 那用户后来把系统调成浅色时，页面还是深色——因为你已经忘了他当初选的是"跟随"。

系统主题变化时要跟着变
if (mq.addEventListener) mq.addEventListener('change', apply);
else if (mq.addListener) mq.addListener(apply);   // 老浏览器的写法

因为 apply() 每次都重新读偏好，所以只有偏好是 system 时， 系统变化才会真的影响页面——不用额外写判断。

要点三：默认深色，而且不能闪一下白的

每个 HTML 文件的第二行
<html lang="zh-CN" data-theme="dark">
⚠️ 这行硬编码不是多余的

如果不写，浏览器会先按 CSS 里的 :root 渲染成浅色， 等 JS 跑完才切成深色——用户会看到白屏闪一下，很难受。

直接在 HTML 里写死 data-theme="dark"，页面一开始就是深色， JS 只在用户选了别的时候才去改它。这正好也满足了「默认深色」这条要求。

按钮的高亮状态

// JS：给当前选中的按钮加标记
btns[i].setAttribute('aria-pressed', String(btns[i].dataset.themeSet === pref));
/* CSS：被标记的按钮变成高亮 */
.theme-switch button[aria-pressed="true"]{ background:var(--accent); color:#fff; }

用 aria-pressed 而不是自定义的 class，顺带把无障碍也做了—— 读屏软件能读出"这个按钮是按下状态"。

8. 拆解：代码块一键复制

把鼠标移到本页任何一个代码块上，右上角会出现「复制」按钮。实现分三步：

① 页面加载后，给每个代码块自动插一个按钮
function addCopyButtons() {
  var blocks = document.querySelectorAll('.codeblock');
  for (var i = 0; i < blocks.length; i++) {
    if (blocks[i].querySelector('.copy')) continue;   // 已经有了就跳过
    var b = document.createElement('button');
    b.className = 'copy';
    b.textContent = '复制';
    blocks[i].appendChild(b);
  }
}
② 用「事件委托」监听点击
document.addEventListener('click', function (e) {
  var btn = e.target.closest('.codeblock .copy');
  if (!btn) return;                                   // 点的不是复制按钮，忽略
  var code = btn.closest('.codeblock').querySelector('code');
  navigator.clipboard.writeText(code.innerText).then(done, fallback);
});
💡 事件委托（Event Delegation）

一句话：不给每个按钮单独装监听器，而是在整个文档上装一个， 点击时再判断"点的是不是我关心的东西"。

类比：不给每个房间装门铃，而是在大门口装一个， 有人按了再问"你找几号房"。

好处：按钮是后来用 JS 插进去的，如果用传统写法， 得等按钮插完再挨个绑定；事件委托完全不用操心这个顺序。

③ 兜底：本地文件打开时剪贴板可能被禁
function fallback() {
  var ta = document.createElement('textarea');
  ta.value = text;
  ta.style.position = 'fixed';
  ta.style.opacity = '0';           // 藏起来，别让用户看见
  document.body.appendChild(ta);
  ta.select();
  try { document.execCommand('copy'); done(); }
  catch (err) { btn.textContent = '请手动复制'; }
  document.body.removeChild(ta);
}
⚠️ 为什么必须写这个兜底

你是用双击文件的方式打开这些 HTML 的，地址栏是 file:// 开头。 部分浏览器在这种协议下禁用现代剪贴板 API。 没有兜底的话，复制按钮点了没反应，而且不报错——最难查的那种 bug。

9. /export：给对话留一份原始底稿

/export my-session.txt
用法行为
/export 文件名直接把当前对话写成纯文本文件
/export（不带参数）弹出对话框，选复制到剪贴板或另存为文件
💡 推荐的用法

在调用 /kb 之前先 /export 存一份。 这样万一整理时漏了什么，你手上还有完整的原始记录可以回查， 而不用重新把对话再走一遍。

注意它只有纯文本一种格式。想要带分析的 HTML 报告，用的是另一个命令：/insights。
