技能入门：把长提示词存成一个 /命令

上一章讲了提示词该怎么写。这一章解决第二个问题：写好了，存到哪？
答案是「技能」。学完这一章，你能在 5 分钟内做出属于自己的第一个 /命令。

1. 技能是什么

技能（Skill）

skill · SKILL.md

1一句话定义
一个存在硬盘上的文本文件，里面写着一段提示词。你打 /文件夹名， 就等于把这个文件的内容整段发出去。
2生活化类比
像输入法里的「常用短语」：你把「本人身份证号 XXX，收货地址 YYY」存成一个短语， 以后打两个字就出来了。技能就是这个，只不过存的是几百字的工作流程， 而且还能带附件（模板文件、脚本）。
3在体系中的位置
技能是「可复用工作流」那一类内容的归宿。 它和后面要讲的输出风格（第 04 章）、CLAUDE.md（第 05 章）是并列关系， 三者分工不同：技能是「用的时候才加载」，另外两个是「一直都在」。
4最小例子
整个技能就是这一个文件：~/.claude/skills/hello/SKILL.md
---
description: 用三句话打个招呼
---

用三句话跟我打招呼，语气轻松一点。

存好之后，在会话里打 /hello，就等于把「用三句话跟我打招呼……」这句话发出去了。

5常见误区

❌ 以为技能是「装了一个插件、多了一个功能」。不是。 技能没有给 Claude 任何新能力，它只是把你本来要打的字提前存好了。

❌ 以为技能只能你手动调。默认情况下 Claude 也能自己判断什么时候该用它 （靠 description 那一行）。想禁止它自作主张，见第 03 章。

2. SKILL.md 长什么样：两个部分

每个技能都是一个文件夹，里面必须有一个叫 SKILL.md 的文件。这个文件分两段：

SKILL.md 的结构
---                                    ← 三个减号，开始
description: 这个技能是干什么的         ← 前置数据区
disable-model-invocation: true
---                                    ← 三个减号，结束

这里往下是正文，就是普通的 Markdown。      ← 正文区
你想让 Claude 做什么，就在这里写清楚。
部分叫什么写什么必填吗
上半段 前置数据（Frontmatter） 配置项。用 键: 值 的格式，夹在两行 --- 之间 整体可省略；但强烈建议至少写 description
下半段 正文 你的提示词本体，普通 Markdown 是
⚠️ description 这一行不只是注释

它有一个实际作用：Claude 靠它判断什么时候该自动调用这个技能。 所以别写「一个技能」这种废话，要写清楚「做什么 + 什么时候用」。

❌ 没用的写法

description: 整理知识

✅ 有用的写法

description: 把当前对话整理成初学者
中文 HTML 教程。当用户说"整理成知识 /
做成笔记 / 生成教程"时使用。

还有个上限要知道：description 在技能列表里 超过 1536 个字符会被截断，所以把最关键的用途写在最前面。

3. 放在哪：四级位置

同一个技能文件，放在不同地方，生效范围完全不同：

级别路径对谁生效适合放什么
个人 ~/.claude/skills/<名字>/SKILL.md 你的所有项目 个人习惯、学习笔记流程 ← 你的场景选这个
项目 .claude/skills/<名字>/SKILL.md 仅当前项目 团队共用的流程，可以提交到 Git 一起分享
插件 <插件>/skills/<名字>/SKILL.md 启用了该插件的地方 打包分发给别人的整套能力
企业 由 IT 部门统一管理的目录 组织内全部用户 公司规范（个人一般用不到）
💡 ~ 是什么意思

~ 代表你的用户主目录。在 Mac 上就是 /Users/你的用户名/。 所以 ~/.claude/skills/ 展开来是 /Users/你的用户名/.claude/skills/。

目录名以点开头（.claude）表示隐藏文件夹，在访达里默认看不见。 在访达里按 Command + Shift + . 可以显示隐藏文件。

Windows 对照（全课唯一一处，记住这三条）：① ~ 对应 C:\Users\你的用户名\，PowerShell 里也能直接写 ~；② 本课的 mkdir -p 在 PowerShell 里去掉 -p 直接 mkdir，它默认就会建出中间目录；③ 访达显示隐藏文件 → 资源管理器里是「查看 → 显示 → 隐藏的项目」。

项目技能还会往上找

如果你在子目录里启动 Claude Code，它会一路往上找到仓库根目录， 把沿途每一层的 .claude/skills/ 都加载进来。所以在子目录里启动， 照样能用到根目录定义的技能。

4. 目录名 = 命令名

这条规则很简单，但初学者经常搞错：

✅ 记住这一条

在个人技能和项目技能里，你打的命令名来自「文件夹名」，不是前置数据里的 name 字段。

文件位置你打什么
.claude/skills/deploy-staging/SKILL.md/deploy-staging
~/.claude/skills/kb/SKILL.md/kb
.claude/commands/deploy.md（旧写法）/deploy（取文件名）
插件里的 my-plugin/skills/review/SKILL.md/my-plugin:review（带插件前缀）
⚠️ 那 name 字段是干嘛的

在个人/项目技能里，name 只影响技能列表里显示的名字，不影响你打的命令。 想改命令名，去改文件夹名。（插件技能是例外，那里 name 会参与命令名。）

5. 重名了谁赢

如果两个地方都有一个叫 deploy 的技能，谁生效？规则是：

情况结果
个人 vs 项目 同名个人的赢
你的技能 vs 同名内置技能你的赢（但内置技能的别名不会被替换）
.claude/commands/deploy.md vs .claude/skills/deploy/技能赢
插件技能不冲突，它有 插件名:技能名 的专属命名空间

6. 重要变化：自定义命令已经并入技能

📌 如果你看过旧教程，这条一定要知道

以前有一个独立的概念叫自定义命令（Custom Commands），放在 .claude/commands/ 目录里。 现在它已经合并进技能了。

.claude/commands/deploy.md.claude/skills/deploy/SKILL.md
产生的命令/deploy/deploy
行为完全一样
旧文件还能用吗✅ 能，不用改—
能带附属文件❌ 不能✅ 能（模板、脚本、参考文档）
能控制谁可以调用❌✅
Claude 能自动加载❌✅

结论：新建的一律用技能写法（skills/名字/SKILL.md）， 已有的 commands/ 文件不用动，它们继续能用。

7. 内置技能：你已经有一堆了

内置技能（Bundled Skills）

bundled skills

1一句话定义
Claude Code 自带的、开箱即用的技能，不用你写任何文件。
2生活化类比
像新买的手机里预装的「计算器」「指南针」——不用去应用商店下，开机就有。
3在体系中的位置
它和你自己写的技能是并列关系，调用方式一模一样（都是打 /名字）， 只是优先级最低——你写一个同名的就会盖掉它（见上一节）。
4最小例子
直接在会话里打就行，不需要任何准备： 
/doctor

它会检查你的 Claude Code 安装配置有没有问题，并尝试修复。

5常见误区

❌ 以为内置技能都会自动触发。不是。有些（比如 /verify） 只有你手动打才会跑，这样长耗时的检查不会自己乱花时间和额度。

❌ 以为它们是「内置命令」。两者不同：内置技能是给 Claude 一段详细提示词， 让它自己用工具去干；内置命令（如 /clear）执行的是固定逻辑。

内置技能干什么
/doctor体检并修复安装配置问题
/code-review审查改动或 PR，找 bug 和可简化的地方
/debug开调试日志、排查问题
/verify构建并运行你的 App，确认改动真的生效（只在你手动调时才跑）
/run启动并操作你的 App，看效果
/run-skill-generator教会 /run 和 /verify 怎么构建启动你这个项目
/batch并行地在整个代码库里做大规模改动
/loop让一段提示词反复执行
/dataviz图表、看板的设计规范
/claude-api加载 Claude API 参考资料
/fewer-permission-prompts扫描历史记录，生成白名单，减少权限弹窗
/design-sync转换 React 设计系统并上传
/deep-research并行发起大量网页检索并交叉验证（标记为「工作流」）
⚠️ 待验证

上面这张表来自官方命令参考页，但抓取时该页面内容被截断， 所以这份清单可能不完整，且会随版本变化。 要看你这台机器上实际可用的完整清单，在会话里输入 /skills， 或者直接打一个 / 看自动补全列表。

如果你不想要这些内置技能占位置，可以在设置里用 disableBundledSkills 关掉——它会关闭除 /doctor 之外的全部内置技能。

8. 动手：5 分钟做出第一个技能

我们做一个真实有用的：让它总结你还没提交的代码改动，并指出风险。

  1. 建文件夹
    终端里执行
    mkdir -p ~/.claude/skills/summarize-changes

    Windows：见本章前面的 Windows 对照（去掉 -p 即可）。

    mkdir = 建目录，-p = 中间缺哪层就补哪层。

  2. 在里面新建 SKILL.md，写入这些内容
    ~/.claude/skills/summarize-changes/SKILL.md
    ---
description: 总结未提交的改动并指出风险。当用户问"我改了什么""帮我写提交信息""看看我的 diff"时使用。
---

## 当前改动

!`git diff HEAD`

## 要求

用两三条要点总结上面的改动，然后列出你注意到的风险，
例如缺少错误处理、写死的值、需要同步更新的测试。
如果 diff 是空的，就说明没有未提交的改动。
  3. 试一试

    随便进一个 Git 项目，改动一个文件，然后启动 Claude Code。两种调用方式都可以：

    方式一：你手动调
    /summarize-changes
    方式二：让 Claude 自己判断（因为 description 匹配上了）
    我改了什么？
💡 那一行反引号是什么魔法

正文里的 !`git diff HEAD` 叫动态上下文注入： Claude Code 会先在你电脑上跑这条命令，把输出结果替换掉这一行， 然后才把整个文件交给 Claude。

也就是说，Claude 看到的不是「!`git diff HEAD`」这行字， 而是你真实的代码改动内容。这让技能的内容能随环境变化，而不是死的。详见第 03 章。

9. 改完不用重启：实时变更检测

✅ 好消息

Claude Code 会监视技能目录的文件变化。你在 ~/.claude/skills/ 或项目的 .claude/skills/ 里新增、修改、删除技能， 当前会话里立刻生效，不用重启。这让调试技能非常快：改一行 → 直接再调一次看效果。

⚠️ 一个例外

如果你创建的是一个会话开始时还不存在的顶层技能目录（比如项目里本来就没有 .claude/skills/，你现在才建），那需要重启 Claude Code， 它才能开始监视这个新目录。

另外，实时检测只覆盖 SKILL.md 的文本内容。

10. 什么时候该做技能

官方给的判断标准很干脆，就两条：

📌 该做技能的信号

（1）你反复往对话里粘贴同一段指令、清单或多步流程；
（2）CLAUDE.md 里某一节已经从"事实"长成了"流程"。

还有一个很实际的理由——省上下文：

写进 CLAUDE.md写成技能
什么时候进上下文每次会话都全文加载只有调用时才加载正文
平时的成本一直占着位置平时只占 description 那一行
适合放短的、每次都要知道的事实长的、偶尔才用的流程和参考资料

所以官方那句话说得很准：「长篇参考资料放在技能里，不用的时候几乎不花任何成本。」

要点记住这一句
