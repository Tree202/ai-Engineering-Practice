技能进阶：参数、实时数据、附属文件、调用权限

上一章的技能是「一段死的文字」。这一章让它活起来： 能接参数、能读你电脑上的实时数据、能带模板文件， 还能规定谁有权调用它。
前置知识：第 02 章。

本页内容
  1. 前置数据字段全表
  2. 控制谁能调用：两个开关
  3. 接收参数：$ARGUMENTS 和它的兄弟
  4. 内置变量：不用写死路径
  5. 动态上下文注入：把命令输出塞进提示词
  6. 附属文件：让技能带模板和脚本
  7. 预授权工具：allowed-tools

1. 前置数据字段全表

技能的所有配置都写在文件开头两行 --- 之间。所有字段都是可选的， 只有 description 强烈建议写。下面按用途分组，方便你查。

① 身份与触发

字段作用示例
description最重要。写清"做什么 + 什么时候用"，Claude 靠它决定是否自动加载。省略时会用正文第一段代替见下方说明
when_to_use补充触发场景，比如典型说法、示例请求。会拼接在 description 后面用户说"整理笔记"时
name技能列表里显示的名字。个人 / 项目技能里不影响你打的命令（命令名来自文件夹名）；插件技能是例外—— 那里 name 会成为命令名的最后一段（/插件名:name）知识整理
paths只有在处理匹配这些通配符的文件时，才自动加载该技能src/**/*.ts
⚠️ 1536 字符上限

description 和 when_to_use 合起来在技能列表里 超过 1536 个字符会被截断（这是为了省上下文）。 所以把最关键的用途写在最前面，别把重点埋在后半段。

② 调用权限

字段作用默认
disable-model-invocation设为 true 后，只有你能调，Claude 不能自动加载false
user-invocable设为 false 后，只有 Claude 能调，命令菜单里看不到它true

③ 参数

字段作用示例
argument-hint自动补全时给你的提示，纯提示，不校验[主题名] [输出目录]
arguments给参数起名字，正文里就能用 $名字 代替 $0、$1[issue, branch]

④ 工具与模型

字段作用
allowed-tools调用这一轮内，这些工具不用弹窗问你就能用。下条消息即失效
disallowed-tools技能生效期间，把这些工具从可用池里拿掉
model这个技能生效时用哪个模型。只影响当前这一轮，不写进设置
effort思考投入档位：low / medium / high / xhigh / max
shell正文里 ! 命令用哪个 shell：bash（默认）或 powershell

⑤ 子代理与钩子（子代理见第 06 章，钩子见第 05 章）

字段作用
context: fork在一个隔离的子代理里跑这个技能，不占用主对话——代价是它读不到对话历史（名字很容易让人误会，见第 06 章第 5 节）
agent配合 context: fork，指定用哪种子代理
background只在 context: fork 下有效。设 false 表示等结果回来再继续，默认 true（后台跑）
hooks调用时注册钩子，之后整个会话都保持

⑥ 元信息（一般用不到）

metadata（你自己的键值数据）、license（许可证）、 compatibility（环境要求）。后两个是 Agent Skills 开放标准的字段，Claude Code 接受但不据此做任何事。

💡 布尔值可以怎么写

除了 true / false，还接受 yes no on off 1 0， 大小写随意。（此宽松写法需 v2.1.218 及以上；更早版本只认 true/false。）

⚠️ 想把技能传到 claude.ai 用？字段要减到 6 个

上面这些字段只在 Claude Code 里全部有效。 如果你要把技能上传到 claude.ai、通过 Skills API 使用，或用官方打包脚本打包， 只允许 6 个字段：name、description、license、 compatibility、metadata、allowed-tools。

多写一个就直接报错，不是忽略。报错长这样：

Unexpected key(s) in SKILL.md frontmatter: argument-hint.
Allowed properties are: allowed-tools, compatibility, description,
license, metadata, name

2. 控制谁能调用：两个开关

默认情况下，你和 Claude 都能调任何技能。两个字段可以改变这一点。

只有你能调（disable-model-invocation）

disable-model-invocation: true

1一句话定义
加上这行，Claude 就不能自作主张触发这个技能了，只有你亲手打 /名字 才行。
2生活化类比
像家里那个「总闸」——你可以拉，但不希望智能音箱觉得"该睡觉了"就替你拉了。
3在体系中的位置
它和 user-invocable: false 是一对相反的开关： 前者禁掉 Claude，后者禁掉你。
4最小例子
---
name: deploy
description: 把应用部署到生产环境
disable-model-invocation: true
---

部署 $ARGUMENTS 到生产：
1. 跑测试
2. 构建
3. 推送到部署目标
4. 验证部署成功
5常见误区

❌ 以为它只是"不推荐自动调"。不是，是硬拦截。 Claude 真去调的话，Claude Code 会直接拦下来， 还会告诉它"别换个方式把部署步骤重做一遍"，所以它多半会转而建议你自己打 /deploy。

❌ 忘了它还有个副作用：加了这行以后， description 也不会进上下文了（因为 Claude 反正不需要判断）。 这顺带省了一点点上下文。

前置数据你能调Claude 能调什么时候进上下文适合
（默认，什么都不写）✅✅ description 一直在，正文调用时才加载 大多数情况
disable-model-invocation: true✅❌ description 也不进，你调时才加载正文 有副作用、要你决定时机的：部署、提交、发消息、批量生成文件
user-invocable: false❌✅ description 一直在，Claude 调时才加载正文 纯背景知识，比如「这套老系统是怎么回事」——你打它没意义
💡 对你的场景怎么选

「把对话整理成一堆 HTML 文件」是个重操作——一次生成七八个文件。 你肯定不希望聊着聊着，Claude 觉得"时机成熟了"就自己开始写。 所以这类技能应该加 disable-model-invocation: true。

3. 接收参数：$ARGUMENTS 和它的兄弟

你希望 /kb Claude技能体系 里的「Claude技能体系」能被技能读到。 这就要用字符串替换。

写法拿到什么
$ARGUMENTS你打的全部参数（原样一整串）
$ARGUMENTS[0]第 1 个参数（从 0 开始数）
$0 $1 $2上面那个的简写。$0 是第 1 个，$1 是第 2 个
$名字在前置数据里用 arguments 声明过的具名参数
具名参数的完整例子
---
description: 根据 issue 编号在指定分支上修复问题
argument-hint: [issue编号] [分支名]
arguments: [issue, branch]
---

修复 issue #$issue，在分支 $branch 上操作。
先读 issue 描述，再定位相关代码。

调用时：

/fix-issue 342 feature/login

正文里的 $issue 会变成 342，$branch 会变成 feature/login。

⚠️ 三个容易踩的点

（1）从 0 开始数。$0 是第一个参数，不是第二个。

（2）没传参数会怎样？ 带下标的（如 $2）如果没对应参数，原样留在正文里不变； 具名的（如 $branch）如果没传，会变成空字符串。行为不一样，注意。

（3）正文里没写 $ARGUMENTS 怎么办？ Claude Code 会把参数自动追加到末尾，形如 ARGUMENTS: 你打的内容。 所以就算你忘了写占位符，参数也不会丢。

4. 内置变量：不用写死路径

技能里经常要引用「技能自己目录下的文件」。硬编码路径会在换电脑、换项目时坏掉。 用内置变量就不会：

变量展开成什么时候用
${CLAUDE_SKILL_DIR}这个技能 SKILL.md 所在的目录引用技能自带的模板、脚本
${CLAUDE_PROJECT_DIR}项目根目录引用项目里的脚本或配置
${CLAUDE_SESSION_ID}当前会话 ID做日志、生成带会话标识的文件名
${CLAUDE_EFFORT}当前思考投入档位根据档位调整指令详略
${CLAUDE_PLUGIN_ROOT}插件安装目录仅插件技能里可用
💡 一个巧妙用法

${CLAUDE_SKILL_DIR} 会在两个地方被替换： 正文里，以及 allowed-tools 里的 Bash 规则里。

在这两处用同一个变量，就能做到：技能调用自己带的脚本， 而且不弹权限窗口——因为预授权的路径和实际执行的路径能对上。

5. 动态上下文注入：把命令输出塞进提示词

动态上下文注入（Dynamic Context Injection）

!`command`

1一句话定义
在技能正文里写 !`某条命令`，Claude Code 会先跑这条命令， 把输出替换掉这一行，再把整个文件交给 Claude。
2生活化类比
像邮件群发的「合并域」：模板里写 {姓名}，发出去之前系统替你填成真实姓名。 这里填的不是姓名，而是命令的实时输出。
3在体系中的位置
它让技能从「死的文字」变成「能感知环境的模板」。 这是技能比旧版自定义命令强的地方之一。 注意它和 参数替换 是并列的两种"填空"： 参数来自你打的字，动态注入来自命令的输出。
4最小例子
## 当前改动

!`git diff HEAD`

## 当前分支

!`git branch --show-current`

请根据以上信息，写一条符合规范的提交信息。

Claude 看到的是真实的 diff 内容和分支名，不是这两行命令。

5常见误区

❌ 以为它在 claude.ai 网页版也能用。不能。 这是 Claude Code 专有的正文特性，在 claude.ai 聊天里和通过 API 都不生效。

❌ 忽略命令失败的后果。见下面的警告。

🚫 命令失败会中止整个技能调用

用默认的 bash 时，任何非零退出码都算失败，会直接中止这次技能调用。

只有一个例外：搜索和比较类命令（如 grep、diff）的 退出码 1 被当作正常结果，输出照常注入——因为对它们来说"1"只是"没找到"。 退出码 2 及以上，即使是这类命令也算失败。

实用对策：给可能失败的命令加个兜底，例如 !`git diff HEAD || echo "（不是 git 仓库）"`。

限制具体行为
超时默认 2 分钟。超时后如果该命令能被转到后台，技能照常渲染，注入的文字会说明"已转后台"并给出输出文件；不能转后台的则被杀掉，这次调用中止
输出体积超过上限时，注入的不是被截断的文字，而是一个文件路径 + 一小段预览
Shell默认 bash；写 shell: powershell 可改用 PowerShell

6. 附属文件：让技能带模板和脚本

这是技能相比旧版自定义命令最大的优势：一个技能是一个文件夹， 里面可以放不止 SKILL.md。

一个带附属文件的技能长这样
~/.claude/skills/kb/
├── SKILL.md          ← 必需。总纲和导航
├── template.html     ← 页面模板，让 Claude 照着填
├── reference.md      ← 详细参考资料，需要时才读
└── scripts/
    └── build.sh      ← 脚本，被执行，不进上下文

关键在于「按需加载」

要让 Claude 知道每个文件是干什么的、什么时候该读，必须在 SKILL.md 里写明：

在 SKILL.md 里这样引用
## 样式

生成页面时，直接复用同目录下的 [template.html](template.html)：
把它的 <style> 和 <script> 原样复制进每个页面，
只替换 <title>、导航链接和 <main> 内容。

## 更多参考

- 完整字段说明见 [reference.md](reference.md)
💡 官方建议

SKILL.md 控制在 500 行以内，详细参考资料挪到独立文件。 理由见第 8 节「技能内容生命周期」——SKILL.md 一旦加载就整轮会话都占着位置。

7. 预授权工具：allowed-tools

正常情况下，Claude 每次要跑命令、写文件，都可能弹窗问你「允许吗」。 allowed-tools 可以让某个技能在调用的那一轮内免问。

---
description: 汇总 git 状态
allowed-tools: Bash(git status:*) Bash(git diff:*) Read
# 分隔符用空格、逗号或 YAML 列表都合法（官方文档原文），07 章的逗号写法同样正确
---
要点说明
有效期只在调用它的那一轮。你发下一条消息，授权就清空了（但技能正文还留在上下文里）
不是限制它只加不减。没列出来的工具照样能用，只是会走正常的权限流程
想长期免问去权限设置里加允许规则，而不是靠这个字段
想禁用工具用 disallowed-tools，它会把工具从可用池里拿掉，同样下条消息失效
🚫 安全提醒：别随便跑陌生仓库里的技能

工作区信任机制管不住这个字段。项目技能的 allowed-tools 在你调用时就会生效，哪怕这个文件夹你从来没信任过。

也就是说，一个技能可以给自己授予很大的工具权限。 所以：从别人仓库里拿到的技能，先打开看一眼 allowed-tools 写了什么，再决定要不要跑。

8. 技能内容生命周期（重要）

这一节解释一个很多人纳闷的现象：「为什么技能好像只在第一次有效？」

阶段发生了什么
调用时 渲染后的 SKILL.md 内容作为一条消息进入对话， 并在这个会话里一直留着
之后每一轮 Claude Code 不会再去读那个文件。 所以要贯穿整个任务的要求，得写成持续性指令，不要写成"一次性步骤"
重复调用 渲染结果完全相同 → 只补一句"已加载"，不塞第二份。
渲染结果不同（参数变了、或 ! 命令输出变了）→ 整份再追加一次
自动压缩后 每个技能最近一次的调用会被重新附加，各保留前 5000 token， 所有技能共享 25000 token 总预算，从最近调用的开始填
⚠️ 「技能好像失效了」怎么办

官方的解释是：内容通常还在，只是模型选择了别的做法。三个对策，按顺序试：

  1. 加强 description 和正文的措辞，让它更倾向于继续遵守（回顾 第 01 章的软约束 vs 硬约束）
  2. 如果刚经历过压缩，或中间调了很多别的技能 → 重新调用一次， 把完整内容恢复回来
  3. 需要百分百可靠的话，用「钩子（Hooks）」——它在固定时机执行固定命令， 不依赖模型的判断
💡 这也解释了为什么 SKILL.md 要短

正文一旦加载就整轮会话都在占位置，等于持续的成本。 所以官方建议：写"做什么"，不要长篇叙述"为什么、怎么来的"， 大段资料挪到附属文件里去。

本章小结

你想要用什么
让 Claude 知道何时该自动用它写好 description（前 1536 字符内说清用途）
禁止 Claude 自作主张disable-model-invocation: true
接收命令行参数$ARGUMENTS / $0 / arguments + $名字

塞入实时数据!`命令`（注意非零退出码会中止）
带模板 / 参考资料 / 脚本放进技能文件夹，在 SKILL.md 里说明用途

技能"失效"了先重新调用一次；要绝对可靠就改用钩子
