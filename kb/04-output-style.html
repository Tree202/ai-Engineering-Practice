输出风格：一次设定，每轮生效

「我是初学者，请用中文，讲通俗一点」——这句话你每一轮都想让它记得， 但又不想每一轮都打一遍。
这就是输出风格要解决的问题。

1. 输出风格是什么

输出风格（Output Style）

output style · outputStyle

1一句话定义
一份写好的"人设与表达规范"，它会被直接加进系统提示词，从而影响每一轮回答。
2生活化类比
像给客服定的话术手册：不改变他掌握的业务知识，只改变他怎么说—— 用什么称呼、先说结论还是先说过程、要不要配个表格。
3在体系中的位置
它和技能是并列关系，分工完全不同： 技能管"偶尔要跑的一套流程"，输出风格管"每一轮都要遵守的说话方式"。 官方原话说得很准：输出风格改变的是 Claude 怎么回应，不是它知道什么。
4最小例子
~/.claude/output-styles/diagram-first.md
---
name: Diagrams first
description: 每次解释都先给一张图
keep-coding-instructions: true
---

解释代码、架构或数据流时，先给一张 Mermaid 图展示结构，
然后再用文字说明。
5常见误区

❌ 拿它存项目信息。「我的 API 在 src/api/」这类项目事实 应该放 CLAUDE.md（第 05 章），不是输出风格。 输出风格只管表达方式。

❌ 改完立刻期待生效。不会。见第 7 节。

2. 先搞懂：系统提示词是什么

系统提示词（System Prompt）

system prompt

1一句话定义
在你说第一句话之前就已经给到 Claude 的一大段基础指令， 规定了它是谁、能用什么工具、该怎么干活。
2生活化类比
像员工的岗位说明书：入职第一天就发给他，之后每一天都默认有效， 而不是每次派活时重念一遍。
3在体系中的位置
它是最高优先级、最持久的一层。理解它，就能理解为什么 输出风格（改系统提示词）和 CLAUDE.md（系统提示词之后的一条用户消息） 效果不同——这是第 05 章的核心。
4最小例子
命令行启动时临时往系统提示词末尾加一句： 
claude --append-system-prompt "所有回答用中文"

缺点是每次启动都要带这个参数，所以更适合写在脚本里，不适合日常交互。

5常见误区

❌ 以为你能看到完整的系统提示词。看不到全文，但你可以往里加东西—— 输出风格和 --append-system-prompt 就是两种加法。

3. 内置的五种风格

风格特点什么时候用
Default
（默认）		 Claude Code 原本的系统提示词，为高效完成软件工程任务设计 日常写代码
Proactive
（主动）		 立刻动手，遇到常规决策自己做合理假设而不是停下来问你，倾向行动而非规划 你信任它、希望少被打断时。
注意：它比"自动模式"更激进，但不改变你的权限模式——什么能跑不用问，仍由权限设置说了算
Concise
（简洁）		 直接给结果，不写开场白、不旁白自己在干什么，默认把回答压短——但活还是照样干透；你要解释时它照样展开。报错、安全警告、危险操作确认这三类内容不会被压缩 你已经熟了，只想要结果。
需 v2.1.237 及以上
Explanatory
（讲解）		 干活的同时穿插「洞察」，解释为什么这么实现、这个代码库有什么模式 你现在这种学习阶段
Learning
（学习）		 协作式边做边学：不仅讲洞察，还会在代码里留下 TODO(human) 标记， 让你自己写一小段关键代码 想真正上手练，而不只是看
💡 给你的建议

你正在学 Claude 的各种功能，Explanatory 是最省事的起点——不用写任何文件， 选一下就能让它每次多讲讲"为什么"。等你觉得它讲的角度不对，再照 第 5 节写一个自己的。

4. 怎么切换（⚠️ 老命令已被删除）

🚫 网上的旧教程会坑你

过去有一个独立命令 /output-style 用来切换风格。它已经：

  • v2.1.73 被标记为废弃
  • v2.1.91 被删除

现在打它没有任何反应。这也是 第 01 章第 8 节为什么要求"查文档核对、标版本"的真实来源。

现在的三种切换方式

  1. 终端里用菜单 
    /config

    在里面选 Output style。选完会存到项目本地的 .claude/settings.local.json。

  2. 直接改设置文件
    .claude/settings.local.json
    {
  "outputStyle": "Explanatory"
}

    值就是风格的名字。这也是桌面 App 用户的推荐做法。

  3. 一行命令直接设（较新版本） 
    /config outputStyle=Explanatory

    键=值 这种写法需要 v2.1.181 及以上； 像 /config theme=dark 这种简写键名需要 v2.1.182 及以上。 打 /config --help 可以列出所有能设的键。

💡 桌面 App 里 /config 不弹菜单

官方文档写得很明确：在桌面 App 里跑 /config，会打开「设置 > Claude Code」界面，而不是像终端那样弹出选择菜单。 所以在桌面 App 里换风格，用上面第 2 种方式：直接写 outputStyle 到设置文件里。

VS Code 插件又不一样：用 / 命令菜单里的 Output styles 选（需 v2.1.257+），写入的是同一个文件。

5. 写一个属于你的风格

放哪

级别路径生效范围
个人~/.claude/output-styles/你所有项目 ← 推荐
项目.claude/output-styles/当前项目
企业策略受管设置目录下的 .claude/output-styles/组织统一下发

文件名就是风格名，除非你在前置数据里写了 name。

前置数据只有四个字段

字段作用默认
name风格名，不写就用文件名文件名
description/config 选择器里显示的说明无
keep-coding-instructions是否保留 Claude Code 自带的软件工程指令false
force-for-plugin仅插件用：插件一启用就强制套用这个风格false

给你的场景量身写一个

~/.claude/output-styles/beginner-zh.md
---
name: 小白中文讲解
description: 中文作答，遇到新名词按五步法讲清楚
keep-coding-instructions: true
---

## 语言

- 回答一律用中文。
- 检索和查阅文档时用英文关键词，但不要把用户的中文原话翻译后再理解。

## 读者设定

用户是初学者。遇到用户可能没接触过的名词时，按固定五步讲：

1. 一句话定义，不使用行话
2. 一个生活化类比
3. 它在整个体系中的位置：和已讲过的名词是包含 / 并列 / 替代 / 前置哪种关系
4. 一个能照抄跑通的最小例子
5. 一到两个初学者常见误区

术语首次出现写成「中文（English）」，之后只用中文。

## 表达

- 讲解顺序从易到难，后面的内容只依赖前面已讲过的名词。
- 涉及对比、多个选项、多个字段时，用表格而不是长段文字。
- 涉及命令、配置、路径时，先核对官方文档再回答；
  不确定的明确标「⚠️ 待验证」，不要猜。
💡 注意这里发生了什么

这一个文件，把你原来那段长提示词里的 「我是初学者」「输出中文」「先讲概念」「检索用英文」 全部吸收了。以后这几句话你再也不用打了。

剩下的「生成 HTML、目录规范、主题切换」属于工作流， 归技能管——这就是第 05 章要讲的分工。

6. keep-coding-instructions：留不留编程指令

这是自定义输出风格里最容易出事的一个字段，因为它的默认值是 false。

取值发生什么什么时候选
true 保留 Claude Code 自带的软件工程指令（怎么控制改动范围、怎么写注释、怎么验证结果）， 你的内容加在后面 你还在写代码，只是想换个表达方式 ← 多数情况选这个
false
（默认）		 丢掉那些编程指令 Claude 完全不做软件工程了，比如当写作助手、数据分析助手
🚫 最常见的翻车现场

「我只是想让它用中文回答」→ 写了个自定义风格 → 忘了写 keep-coding-instructions: true → 默认 false 生效，编程指令被丢掉 → 它开始乱改文件、不验证、改动范围失控。

记住：只要 Claude 还要碰代码，就写上 keep-coding-instructions: true。

7. 生效时机：为什么改了没反应

⚠️ 这是初学者第一大困惑

输出风格是系统提示词的一部分，而系统提示词 只在会话开始时读一次。所以你在会话中途改了风格文件或设置， 当前这个会话不会有任何变化。

必须 /clear 开一个新对话，或者干脆重开一个会话。

改完立刻生效？为什么
改技能文件✅ 立刻技能有实时变更检测，且是调用时才读
改输出风格❌ 要 /clear 或新会话系统提示词只在会话开始时读一次
改 CLAUDE.md❌ 要新会话同样在会话开始时加载
💡 顺带一提

/clear 是开一个全新的空对话（旧对话可以用 /resume 找回来）。 如果你只是想腾出上下文空间、但要接着聊，用的是 /compact—— 但 /compact 不会重新加载系统提示词，所以它救不了风格没生效的问题。

8. 作用范围：对子代理无效

这一条现在看可能有点抽象，读完第 06 章会更清楚，先记住结论：

场景输出风格生效吗原因
主对话✅ 生效风格就是加在主对话的系统提示词上的
子代理（Subagent）❌ 不生效子代理用的是它自己的系统提示词
分身（Fork）✅ 生效分身继承父会话完整的系统提示词，是唯一的例外
⚠️ 实际影响

如果你设了"全部用中文"，然后让 Claude 派一个子代理去干活， 子代理返回的内容可能是英文的——因为风格管不到它。

要让子代理也守规矩，得在派活时的那段话里明确写上要求， 或者改用分身（context: fork）。

9. 代价：会多花多少 token

来源影响
输入（你的风格文字本身） 系统提示词变长 → 输入 token 增加。 但提示词缓存会让第一次请求之后的成本降下来
输出（内置 Explanatory / Learning） 刻意设计成回答更长，所以输出 token 会明显增加
输出（内置 Concise） 反过来：它的职责就是把回答压短，输出 token 会明显减少
输出（你自定义的） 取决于你写了什么。要求"每个概念配表格 + 例子"，回答自然就长
💡 权衡建议

风格文件别写成长篇大论——它每一轮都在占位置。 把"每一轮都要遵守的表达规范"放进去（几十行足够）， 把"某个任务的详细步骤"留给技能， 后者只在用到时才花钱。

内置有哪些Default / Proactive / Concise / Explanatory / Learning（共 5 种）
怎么切换/config 或改 outputStyle 设置。/output-style 已删除
