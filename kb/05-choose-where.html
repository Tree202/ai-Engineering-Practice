1. CLAUDE.md 是什么

CLAUDE.md

CLAUDE.md · 记忆文件

1一句话定义
一个普通的 Markdown 文件，放在约定好的位置，每次会话开始时自动加载， 用来告诉 Claude 关于这个项目、或关于你的固定事实。
2生活化类比
像贴在工位显示器边上的便签条：「测试用 npm test」「别直接推 main 分支」。 新人每天来上班第一眼就看到，不用你天天口头交代。
3在体系中的位置
它和输出风格都是"一直生效"的，但位置不同： 输出风格改的是系统提示词； CLAUDE.md 是系统提示词之后的一条「用户消息」（见图 4-1）。
这个差别有实际后果——见下面的误区。
4最小例子
项目根目录的 CLAUDE.md
# 项目约定

- 缩进用 2 个空格
- 提交前跑 `npm test`
- API 处理器放在 `src/api/handlers/`
- 知识库 HTML 输出到 `./kb/`，文件名 `01-xxx.html` 依次编号

不想自己从头写的话，可以让它自动生成一份起点：

/init

它会分析你的代码库，把发现的构建命令、测试方式、项目约定写进去。 如果已经有 CLAUDE.md，它不会覆盖，只会提改进建议。

5常见误区

❌ 以为写进去就一定会被执行。不会。官方说得很直白： CLAUDE.md 是作为「用户消息」送进去的，不是系统提示词的一部分， 它是上下文，不是强制配置。含糊或互相矛盾的指令，遵守度会明显下降。

❌ 把它写成几百行的大百科。它每次会话都全文加载， 越长越占上下文，遵守度反而越低。目标是200 行以内。

🚫 什么时候 CLAUDE.md 一定不够用

如果某件事必须在某个时刻百分百执行（比如"每次提交前都要跑 lint"）， CLAUDE.md 给不了这个保证，因为它只是"建议"。

这时候要用钩子（Hooks）——它在固定的生命周期事件上执行固定的 shell 命令， 不管 Claude 怎么想都会执行。

2. CLAUDE.md 放在哪几个位置

级别路径用途谁能看到
受管策略 macOS：/Library/Application Support/ClaudeCode/CLAUDE.md
Linux/WSL：/etc/claude-code/CLAUDE.md
Windows：C:\Program Files\ClaudeCode\CLAUDE.md		 公司统一规范、合规要求 全组织，个人无法排除
用户 ~/.claude/CLAUDE.md 你的个人偏好，跨所有项目 只有你
项目 ./CLAUDE.md 或 ./.claude/CLAUDE.md 团队共享的项目约定 团队（通过 Git）
本地 ./CLAUDE.local.md 你在这个项目里的私人偏好 只有你（记得加进 .gitignore）
💡 它们不是互相覆盖，而是拼接

Claude Code 会从你的工作目录一路往上走，把沿途每一层的 CLAUDE.md 和 CLAUDE.local.md 都拼接进上下文，而不是只用最近的那个。

顺序是从文件系统根目录往下，所以离你启动位置越近的，读得越晚； 同一层里 CLAUDE.local.md 排在 CLAUDE.md 后面。

子目录里的 CLAUDE.md 不在启动时加载，而是等 Claude 真的去读那个目录里的文件时才加载（主线第 21 页的三层图里，它是第三层）。

⚠️ 想确认到底加载了哪些？

别猜，直接查：

/context

看 Memory files 那一栏。没出现在里面的文件，Claude 就是看不见。 这是排查"我明明写了它却不听"的第一步。

3. 怎么写好一个 CLAUDE.md

原则做法
体积目标 200 行以内。太长会占上下文、降低遵守度
结构用标题和短列表分组。Claude 和人一样，扫结构比读大段文字快
具体写能验证的话（呼应第 01 章的硬约束）
一致定期清理过时和互相矛盾的条目。两条规则打架时，Claude 可能随便挑一条

❌ 模糊

- 代码要格式化好
- 记得测试
- 文件组织得清楚点

✅ 具体

- 缩进用 2 个空格
- 提交前跑 `npm test`
- API 处理器放 `src/api/handlers/`
💡 什么时候该往 CLAUDE.md 里加一条

官方给了四个信号，非常实用：

  • Claude 第二次犯同一个错
  • 代码审查抓到了一个"它本该知道"的问题
  • 你又打了一遍上次打过的那句纠正
  • 新同事来了也需要知道这件事

反过来，如果某条内容是多步流程，或者只在代码库某一块才有用， 就该挪到技能或路径作用域规则里去。

💡 两个小技巧

（1）留给人看的笔记不占 token。CLAUDE.md 里的 块级 HTML 注释 <!-- 维护者备注 --> 会在送进上下文之前被剥掉。 用它给人类维护者留话，不花上下文。

（2）已经有 AGENTS.md 怎么办？Claude Code 只读 CLAUDE.md，不读 AGENTS.md。 建一个 CLAUDE.md 把它导入进来即可：

CLAUDE.md
@AGENTS.md

## Claude Code 专用

改 src/billing/ 下的文件时，先用计划模式。

4. 导入其他文件：@路径

CLAUDE.md 可以用 @路径 把别的文件整个拉进来：

项目概览见 @README，可用命令见 @package.json。

# 补充说明
- git 工作流 @docs/git-instructions.md
规则说明
路径类型相对路径、绝对路径都行。相对路径相对于「写这行的那个文件」，不是工作目录
嵌套深度被导入的文件还能再导入，最多 4 层
不想导入怎么办用反引号包起来：写 `@README` 就只是普通文字。 代码块和行内代码里的 @ 都不会被当成导入
加载时机启动时就展开加载。所以拆成导入只是为了组织清晰，并不省上下文
⚠️ 外部导入会弹一次批准框

如果项目级的记忆文件里，某个导入的路径解析到了工作目录之外（比如导入你主目录里的文件）， Claude Code 第一次会弹出批准对话框列出这些文件。你拒绝的话，这些导入就永久停用、也不再弹。

这是在保护你：防止别人往共享项目里提交一个偷偷读你本地文件的导入。 你自己 ~/.claude/ 下的记忆文件不受此限——那是你自己写的。

5. .claude/rules/：按文件类型分开加载

项目规则（Project Rules）

.claude/rules/*.md

1一句话定义
把 CLAUDE.md 拆成一堆按主题分的小文件，还能规定 「只有在处理某类文件时才加载」。
2生活化类比
公司手册太厚没人看，于是拆成「财务篇」「差旅篇」「安全篇」， 而且只在你真的要报销时才把财务篇发给你。
3在体系中的位置
它是 CLAUDE.md 的拆分方案（不是替代品）。 和技能的区别： 规则是「符合条件就自动进上下文」，技能是「调用才进」。
4最小例子
.claude/rules/api.md
---
paths:
  - "src/api/**/*.ts"
---

# API 开发规则

- 所有接口必须做输入校验
- 使用统一的错误响应格式
- 补上 OpenAPI 文档注释

只有当 Claude 去读 src/api/ 下的 TypeScript 文件时，这些规则才会进上下文。

5常见误区

❌ 以为不写 paths 也能省上下文。不写 paths 的规则 会无条件在启动时加载，和 .claude/CLAUDE.md 同等优先级。 省上下文靠的是 paths。

❌ 用它存"偶尔才跑的流程"。那种应该用技能——官方明确这么建议。

通配符匹配
**/*.ts任意目录下所有 TypeScript 文件
src/**/*src/ 下所有文件
*.md项目根目录下的 Markdown 文件
src/**/*.{ts,tsx}大括号可以一次匹配多个扩展名

个人级的规则放 ~/.claude/rules/，对所有项目生效； 它比项目规则先加载，所以项目规则优先级更高。注意方向和第 02 章的技能优先级（企业 > 个人 > 项目）相反——两套独立机制，别记混。

6. 自动记忆：Claude 自己做的笔记

自动记忆（Auto Memory）

auto memory · MEMORY.md

1一句话定义
Claude 自己决定记下来的东西：你的纠正、你的偏好、它摸索出来的构建命令。 你不用写任何文件。
2生活化类比
CLAUDE.md 是你给新人写的入职手册； 自动记忆是新人自己记的工作笔记——你说过"我们这儿用 pnpm 不用 npm"，他记下来了。
3在体系中的位置
它和 CLAUDE.md 是互补的一对，两者都在每次会话开始时加载。 核心区别就一个字：谁写的。
4最小例子
直接跟它说就行： 
记住：这个项目一律用 pnpm，不要用 npm

想看它到底记了什么、或者改掉删掉：

/memory
5常见误区

❌ 以为它会跨机器同步。不会。自动记忆是本机的， 存在 ~/.claude/projects/<项目>/memory/，不会同步到别的电脑或云端。（按官方文档：在 git 仓库里记忆按仓库划分，同一仓库的多个工作树共用同一份；不在仓库里则按项目路径各自生成——和下表「范围」说的是同一件事。）

❌ 把大段内容塞进 MEMORY.md。只有前 200 行或前 25KB（先到者为准） 会在会话开始时加载，超出的部分直接不加载。详细内容应该拆到同目录的主题文件里， 那些是用到时才读的。

CLAUDE.md自动记忆
谁写你Claude
内容指令和规则它学到的经验和模式
范围项目 / 个人 / 组织按 Git 仓库划分，同仓库的多个工作树共用一份
加载量全文加载只加载 MEMORY.md 前 200 行或 25KB
关闭方式删掉文件设置里 autoMemoryEnabled: false， 或环境变量 CLAUDE_CODE_DISABLE_AUTO_MEMORY=1

看到界面上闪过「Saved 2 memories」「Recalled 2 memories」，就是它在读写这个目录。 这些都是普通的 Markdown 文件，你随时能打开改或删。

7. 五种定制方式全对比

方式工作原理什么时候用生效范围
输出风格 修改系统提示词 你想要一个不同的角色、语气、默认回答格式，每一轮都要 主对话；子代理无效，分身有效
CLAUDE.md 作为系统提示词之后的一条用户消息加入 Claude 每次都该知道的项目约定和事实 会话全程；子代理也会加载（Explore/Plan 除外）
--append-system-prompt 往系统提示词追加，不删除任何东西 单次启动的一次性追加。每次都得带这个参数，适合脚本 本次启动
子代理 跑一个独立的助手，有自己的系统提示词、模型、工具 需要一个作用域独立的专职帮手 见第 06 章
技能 在被调用或被判定相关时，加载一段任务指令 你有一套可复用的工作流 调用后整轮会话常驻

9. 把你那段长提示词拆开

现在用上面的决策图，把一段真实的长提示词拆掉。原文是：

拆之前：每次都要重打的一整段
我是初学者，学习 claude 的各种功能。
我输入的内容全部转换为英文，你使用英文搜索分析。你输出的结果输出中文。
我是小白，当遇到没有接触过的名词和功能时，先讲清名词概念、逻辑关系、使用方法。
你的讲解要：从易到难、有逻辑性、有条理性、用通俗易懂的例子。
输出内容不限于：文字 表格 列表 图片，并且有三种主题（浅色/深色/跟随系统，默认深色）。
把上面讲解的知识生成 html，内容不丢失，图文并茂。
输出内容长度和大小不限制。
当一个 html 文件长度适合阅读，可以生成多个 html 文件。
原句属于去处
我是初学者 / 输出中文 / 检索用英文每轮的说话方式输出风格 ~/.claude/output-styles/beginner-zh.md
遇到新名词先讲清概念、从易到难每轮的说话方式输出风格（改写成五步法）
输出到 ./kb/、文件名规范项目事实CLAUDE.md
整理对话 → 核实 → 逐个生成 → 自检多步流程技能 ~/.claude/skills/kb/SKILL.md
三种主题、配色、样式可复用资产技能目录里的 模板文件 template.html
「输出长度不限制」删掉，改成「写一个存一个」（见 第 01 章第 4 节）
「不限于…等等」「适合阅读」改写成可数的硬约束（见 第 01 章第 5 节）
✅ 拆完之后

你每次要做的，从粘贴 300 字变成：

/kb Claude 技能体系

而且因为样式来自同一个模板文件，每次生成的页面外观完全一致， 不会这次橙色下次蓝色。完整实施步骤见第 07 章。

10. 压缩之后哪些会活下来

回顾第 01 章：上下文满了会触发压缩，细节会丢。 但不是所有东西都会丢——不同来源的内容命运不同：

内容来源压缩后
项目根目录的 CLAUDE.md ✅ 存活。Claude Code 会重新从磁盘读一遍再注入回去
子目录里的 CLAUDE.md ⚠️ 不自动重注入。等下次 Claude 读那个目录里的文件时才会重新加载
带 paths 的规则 ⚠️ 同上，要等下次匹配到文件
技能内容 🟡 部分存活。每个技能最近一次调用会被重新附加， 各留前 5000 token，全部技能共享 25000 token 预算，从最近的开始填
你在对话里临时说的话 ❌ 只剩摘要
⚠️ 一个非常实用的推论

如果某条指令「压缩之后就失灵了」，原因几乎总是这三个之一：

  1. 它只在对话里说过，没写进任何文件 → 写进 CLAUDE.md
  2. 它在子目录的 CLAUDE.md 里，还没被重新触发
  3. 它是路径作用域规则，从压缩以来还没匹配到文件

11. 相关命令速查

命令作用
/init分析代码库，自动生成一份起始 CLAUDE.md。已有则只提建议不覆盖
/memory列出所有记忆文件位置并可直接打开编辑；也能开关自动记忆
/context看上下文占用的彩色方格图，并确认哪些记忆文件真的加载了
/config打开设置界面（主题、模型、输出风格等）。别名 /settings
/skills列出当前可用的全部技能
/compact [说明]压缩当前对话腾出空间，可附一句话指定摘要重点
/clear [名字]开一个全新空对话。可给旧对话起个名，方便 /resume 找回。别名 /reset /new
/export [文件名]把当前对话导成纯文本。带文件名直接写文件，不带则弹框选复制或另存
/insights生成一份 HTML 报告，分析你最近的会话：常在哪些项目干活、怎么用 Claude Code、哪里容易出问题、有哪些功能值得试。云端会话不可用
/doctor体检配置。它还会给已提交的 CLAUDE.md 提"瘦身"建议（需 v2.1.206+）
💡 /insights 值得你现在就试一下

你正在学 Claude Code，而 /insights 恰好会告诉你 「你实际上是怎么用它的、哪里出过问题、还有什么功能没用上」， 而且输出正是你喜欢的 HTML 报告。
